# 진행 상황 정리 (7/9)

전날 만들어둔 맵 오브젝트(가구류)를 실제로 배치했는데, 오브젝트 크기가 참고 이미지 대비 지나치게 작다는 문제가 있었다. 원본 비트맵 크기(`m_iSrcCX/CY`)와 실제로 화면에 그릴 크기(`m_iDestCX/CY`)를 분리된 변수로 관리하고 `GdiTransparentBlt`의 목적지 크기만 원본의 일정 배율로 키우는 방식으로 해결했다.

```cpp
m_iSrcCX = 61;   m_iSrcCY = 49;    // 원본 크기 (소스 사각형)
m_iDestCX = 73;  m_iDestCY = 59;   // 실제로 그릴 크기 (1.2배)
...
GdiTransparentBlt(_DC,
    iDestX, iDestY, m_iDestCX, m_iDestCY,   // 목적지 크기만 키움
    hPropDC, 0, 0, m_iSrcCX, m_iSrcCY,       // 소스는 원본 그대로
    RGB(255, 255, 255));
```

가로세로 배율을 다르게 주면 이미지가 찌그러지므로 항상 동일 배율을 곱해야 한다는 점을 확인했다.

사운드 시스템을 본격적으로 붙이는 과정에서 기존 `SoundMgr::PlaySound()`의 재생 조건 로직이 뒤집혀 있는 버그를 발견했다. 채널이 재생 중일 때만 새 사운드를 재생하도록 조건이 걸려 있었는데, 채널이 한 번도 사용된 적 없는 초기 상태(`nullptr`)에서는 이 조건 자체가 성립하지 않아 첫 재생이 씹히는 문제였다.

```cpp
// 수정 전
FMOD_BOOL bPlay = FALSE;
if (FMOD_Channel_IsPlaying(m_pChannelArr[eID], &bPlay))   // 채널이 nullptr이면 여기서 실패 -> 첫 재생 씹힘
{
    FMOD_System_PlaySound(m_pSystem, FMOD_CHANNEL_FREE, iter->second, FALSE, &m_pChannelArr[eID]);
}

// 수정 후
FMOD_System_PlaySound(m_pSystem, FMOD_CHANNEL_FREE, iter->second, FALSE, &m_pChannelArr[eID]);
```

`PlayBGM()`의 매개변수 역시 `const`가 빠져 있어 문자열 리터럴을 바로 넘길 수 없는 상태였는데, 이 역시 함께 고쳤다.

몬스터별 공격/피격/발견/사망 사운드는 기존에 잡아둔 클래스 계층을 그대로 활용해 붙였다. 근접 몬스터 공통 로직에는 기본 사운드를 넣어두고, 보스나 구울처럼 차별화가 필요한 경우에만 해당 가상 함수를 오버라이드해 자기 전용 사운드로 교체하는 식이다.

```cpp
// CMonster_Melee - 공통 기본 사운드
virtual void Play_AttackSound();
...
void CMonster_Melee::Play_AttackSound()
{
    CSoundMgr::Get_Instance()->PlaySound(_T("snd_skill_killing_swing_startcast.wav"), CSoundMgr::MONSTER);
}

// CAncientTroll - 자기 전용으로 교체
void CAncientTroll::Play_AttackSound()
{
    CSoundMgr::Get_Instance()->PlaySound(_T("snd_troll_boss_troll_regeneration_cast.wav"), CSoundMgr::MONSTER);
}
```

몬스터의 "발견" 시점은 매 턴 거리를 재계산하는 구조라 상태를 별도로 추적하지 않으면 시야에 들어올 때마다 매번 재생되므로, 최초 발견 여부를 나타내는 플래그를 두어 시야 진입 시 한 번만 재생하고 시야를 벗어나면 다시 초기화하도록 했다.

```cpp
if (iDistance > MONSTER_SIGHT_RANGE)
{
    m_bAlerted = false;   // 시야에서 벗어나면 다시 발견 전 상태로
    return;
}

if (!m_bAlerted)          // 시야 범위 안에 처음 들어온 순간에만
{
    m_bAlerted = true;
    Play_AlertSound();
}
```

참고로 원거리 몬스터는 근접 몬스터와 상속 계층이 분리되어 있어 이 로직을 별도로 추가해줘야 했다.

배경음악은 메뉴, 평상시 던전, 보스전용으로 세 종류를 두고 상황에 따라 전환되게 했다. 보스를 처음 발견하는 시점(위의 발견 감지 로직과 동일한 지점)에서 평상시 BGM을 멈추고 보스전 BGM으로 바꾸고, 보스가 사망하는 시점에 다시 평상시 BGM으로 복귀시켰다.

```cpp
void CAncientTroll::Play_AlertSound()
{
    CSoundMgr::Get_Instance()->PlaySound(_T("snd_troll_boss_alert.wav"), CSoundMgr::MONSTER);
    CSoundMgr::Get_Instance()->StopSound(CSoundMgr::BGM);
    CSoundMgr::Get_Instance()->PlayBGM(_T("snd_prologue_boss_battle.ogg"));
}
```

인벤토리 쪽에서는 장비 드래그·장착 시점에 사운드를 붙이는 김에, 사망 후 재시작 시 이전 세션에서 장착했던 아이템 상태가 인벤토리 싱글톤에 그대로 남아있던 버그도 함께 발견해 고쳤다. 씬이 바뀌어도 유지되는 매니저 클래스에 이전 실행 상태가 남아있어 문제가 되는 패턴은 이전에도(오브젝트 매니저, 카메라 스크롤 등에서) 반복적으로 나타났던 것이라, 이번에도 초기화 시점에 이전 상태를 정리하는 동일한 방식으로 해결했다.

```cpp
void CInven::Initialize()

    SAFE_DELETE(m_pArmorItem);
```

마지막으로 보스에게 공격 모션과 사망 모션을 추가했다. 기존 대기 애니메이션과 달리 이 둘은 반복 재생이 아니라 한 번만 재생되고 끝나야 하는 성격이라, 재생 중 여부를 나타내는 별도 상태와 프레임 카운터를 추가로 두었다.

사망 모션은 별도의 고민이 필요했는데, 기존 구조에서는 체력이 0이 되는 즉시 사망 처리가 이루어져 애니메이션이 재생될 시간이 없었다. 이를 위해 보스의 피격 처리 함수를 더 이상 부모 클래스에 위임하지 않고 필요한 부분(데미지 적용, 이펙트 생성, 경험치 지급)을 직접 구현하되, 체력이 0 이하가 되는 순간에는 즉시 사망 처리하는 대신 "사망 진행 중" 상태로 전환하고 사망 애니메이션이 끝까지 재생된 뒤에야 실제 사망 처리가 이루어지도록 분리했다.

```cpp
if (m_iHp <= 0)
{
    m_bIsDying = true;                       // 즉시 죽이지 않고 상태만 전환
    m_tDeadFrame.iStartX = 0;
    m_tDeadFrame.dwTime = GetTickCount();
    Play_DeathSound();
    ...
}

// Update()
if (m_bIsDying)
{
    if (/* 프레임 재생 시간 도달 */)
    {
        ++m_tDeadFrame.iStartX;
        if (m_tDeadFrame.iStartX >= m_tDeadFrame.iEndX)
        {
            m_bDead = true;      // 애니메이션 끝까지 재생된 뒤에야 진짜 사망 처리
            return OBJ_DEAD;
        }
    }
    return OBJ_NOEVENT;
}
```

이 상태에서는 턴 행동(추격, 공격)도 하지 않도록 `On_Turn()`을 별도로 오버라이드해서 막아, 애니메이션이 재생되는 동안 보스가 계속 움직이는 어색한 상황을 방지했다.
