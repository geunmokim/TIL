## 2. 새로 나온 것 — `PushID`/`PopID`

맵 격자 48칸이 전부 라벨 없는(`""`) 버튼이라, ImGui가 헷갈리지 않게 칸마다 `PushID(고유번호)`~`PopID()`로 구분해줌. 라벨이 서로 다른 버튼(`SlotNames[i]`처럼)엔 필요 없었는데, 라벨이 같거나 없는 버튼을 여러 개 만들 땐 항상 필요.

## 3. `Push`/`Pop` 계열 함수들 — 스택(Stack) 구조 총정리

이번에 여러 번 나온 `PushStyleColor`/`PopStyleColor`, `PushID`/`PopID`, `TreeNode`/`TreePop`, `Begin`/`End`, `Columns(N)`/`Columns(1)` 전부 **스택(후입선출, LIFO)** 원리를 공유함.

- **스택 vs 큐**: 스택(LIFO) = 나중에 넣은 게 먼저 나감(접시 쌓기). 큐(FIFO) = 먼저 넣은 게 먼저 나감(줄서기). `Push`/`Pop`은 스택 전용 용어(큐는 보통 `Enqueue`/`Dequeue`).
- **왜 스택이 필요한가**: "바깥 설정 유지한 채 안쪽에서 잠깐 다른 설정으로 덮어씌우고, 다시 원래대로 복귀"하는 **중첩 구조**를 표현하려면 스택이 자연스러움. C++ 함수 호출 자체도 콜스택(LIFO)으로 동작하는 것과 같은 맥락.
- **STL과의 관계**: `std::stack`도 실제로 `push()`/`pop()`이라는 같은 이름을 씀 — ImGui가 새로 만든 용어가 아니라 컴퓨터공학 표준 용어를 그대로 가져다 쓴 것.
- **주의**: `Push`/`Pop`이라는 이름이 100% "내부가 스택 자료구조"라는 법적 보증은 아님 (예: `git push`/`pull`은 스택과 무관한 일반적 의미). 다만 **C++ API/라이브러리, 특히 그래픽스·UI 계열에서는 Push-Pop 짝으로 보이면 스택이라고 판단해도 실무적으로 거의 다 맞음** — ImGui 외에도 Win32 `SaveDC`/`RestoreDC`, 예전 OpenGL `glPushMatrix`/`glPopMatrix` 등이 같은 관례.
- **규칙**: `Push` 한 번엔 `Pop`도 반드시 한 번, 짝을 맞춰야 함. 안 맞추면 그 설정이 이후 위젯에 계속 남음.

## 4. DX11로 넘어갔을 때 지금 만든 맵툴이 어떻게 업그레이드되는지

| | 지금 (ImGui 맵) | DX11 업그레이드 후 |
|---|---|---|
| 맵 형태 | ImGui 버튼 48개 (2D UI) | 실제 3D 지형(Terrain) 메시가 렌더링됨 |
| 클릭 좌표 얻는 법 | 버튼 인덱스로 바로 나옴 | 화면 클릭 좌표 → 3D 월드 좌표 변환 필요 (**Picking**) |
| 데이터 저장 | `m_MapData[y][x]` | 개념 동일 — Terrain의 타일/셀에 정보 저장 |

**Picking**(화면 2D 클릭 → 3D 공간 좌표 변환) 개념만 새로 배우면 되고, "클릭한 지점에 선택값을 기록한다"는 로직 자체는 지금 짠 것과 동일하게 재사용됨. DX11 자료의 `2일차_Picking`에서 다룰 내용. 팔레트(선택 UI)는 그대로 ImGui로 남고, 실제 맵만 DX11 3D 렌더링으로 바뀌는 구조:
```
[ImGui 팔레트] 클릭 → m_iSelectedSlot 갱신 (지금과 동일)
        ↓
[DX11 3D 지형] 클릭 → Picking으로 3D 좌표 계산 → 타일 인덱스 계산
        → m_MapData[해당 타일] = m_iSelectedSlot (지금 로직 재사용)
```
