# Day5 정리: 구조체로 데이터 묶기

## 1. 핵심 변화 — 흩어진 변수 → 구조체

Day3~4까진 `m_bCheck`, `m_fValue`처럼 변수 하나하나 따로 위젯에 연결했는데, 이번엔 관련 데이터를 구조체로 묶었어요.

```cpp
struct MonsterData
{
	char	Name[32] = "Ghoul";
	int		Hp = 80;
	float	Atk = 12.5f;
	bool	bLarge = false;
	float	Color[3] = { 0.6f, 0.2f, 0.2f };
};
```

**왜 이렇게 바꾸냐면**: 몬스터가 여러 마리로 늘어나면 `MonsterData` 배열 하나로 관리 가능하고, 나중에 Day8(저장/불러오기)에서 파일에 쓸 때도 구조체 하나만 통째로 쓰면 되니까 훨씬 다루기 편해짐.

## 2. 새로 배운 위젯 3개

```cpp
ImGui::InputText(u8"이름", m_Monster.Name, sizeof(m_Monster.Name));
// 라벨       연결할 char배열     배열 크기 (버퍼 넘침 방지, 꼭 넣어야 함)

ImGui::InputInt(u8"체력(HP)", &m_Monster.Hp);
// 슬라이더 없이 숫자 직접 타이핑. 옆에 -/+ 버튼 자동으로 붙음

ImGui::ColorEdit3(u8"색상", m_Monster.Color);
// 클릭하면 색상 팔레트 뜸, float[3]에 R/G/B(0.0~1.0) 저장
```

## 3. `ImGui::Separator()`

가로 구분선 하나를 그려서 위젯 그룹을 시각적으로 나누는 함수. `printf`의 `\n`(그냥 줄바꿈)과 다르게, **실제로 화면에 선이 렌더링**된다는 게 차이. 데이터에는 아무 영향 없는 순수 장식용.

## 4. `u8` 접두사와 `/utf-8` 옵션의 관계 — 정확히 정리

| | 역할 | 언제 필요 |
|---|---|---|
| `/utf-8` (컴파일러 옵션) | 소스 파일 자체를 UTF-8로 읽으라고 강제 | 한글(비ASCII)이 소스 코드 어디든 들어가는 프로젝트라면 항상 |
| `u8"문자열"` (리터럴 접두사) | 그 문자열을 무조건 UTF-8 바이트로 인코딩 | ImGui처럼 UTF-8을 기대하는 대상에 문자열 넘길 때 |

`/utf-8`은 "한글 쓰는 모든 프로젝트에 기본 장착", `u8`은 "그중에서도 ImGui한테 넘길 문자열에 붙이는 습관" — 둘이 짝을 이뤄서 한글이 안전하게 전달됨. 예전에 겪은 브레이스 어긋남/문자열 안 닫힘 에러들은 전부 `/utf-8` 관련 문제였음(파일이 실제로 UTF-8로 저장 안 돼 있으면 옵션이 있어도 깨짐 — 파일 인코딩 자체를 "UTF-8 서명 포함"으로 다시 저장해야 했던 사례).

## 5. `Struct.h` 분리

구조체가 앞으로 계속 늘어날 걸 감안해서, `MonsterData`를 `MainGame.h`에서 빼서 **`Struct.h`라는 별도 파일**로 옮김.

```cpp
// Struct.h
#pragma once
struct MonsterData { ... };
```

`MainGame.h`는 `#include "Struct.h"` 한 줄만 추가하면 됨. `MainGame.cpp`는 안 바뀜 (구조체 사용하는 코드는 그대로, 어디서 타입을 가져오는지만 달라짐). 앞으로 구조체 늘어나면 전부 이 파일에 모아둘 예정.

## 확인한 것
`InputInt`의 `-`/`+` 버튼, `ColorEdit3`의 RGB 슬라이더+미리보기까지 전부 정상 동작 확인. 맨 아래 요약 텍스트에 모든 값이 실시간 반영되는 것도 확인.
