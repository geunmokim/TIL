# 진행 상황 정리

구울(Ghoul) 몬스터를 추가하면서, 처음엔 `CMonster_Melee`를 상속받는 별도 클래스로 만들었다가, 이후 Small/Large 두 개체가 스탯과 스프라이트만 다르고 로직은 완전히 동일하다는 점에 착안해 `GHOUL_SIZE` enum을 받는 생성자 방식의 단일 클래스(`CGhoul`)로 통합했다. 이 과정에서 기존 `CMonster_Melee`가 사실상 밴딧 하나만을 위한 구체 클래스로 굳어 있던 문제를 함께 정리했는데, 밴딧 전용 초기화 코드를 `CBandit_Cleaver`라는 별도 자식 클래스로 분리하고, `CMonster_Melee`는 `CNewMonster`처럼 근접 몬스터들의 공통 로직(이동, 공격, 데미지 처리)만 갖는 순수 부모로 되돌렸다. 결과적으로 밴딧/구울처럼 로직이 같고 데이터만 다른 경우는 enum 기반 단일 클래스로, 스킬처럼 행동 자체가 달라질 여지가 있는 경우는 상속으로 분리한다는 기준을 세우고 그에 맞춰 구조를 재정비한 셈이다.

던전에 구울을 배치할 때는 `Tile.dat` 바이너리를 직접 파싱해서 타일 좌표를 텍스트 맵으로 복원한 뒤, 플레이어 시작 방과 인접한 빈 방들의 바닥 좌표를 눈으로 확인하고 배치했다. 이 과정에서 벽 안쪽 좁은 통로나 문틀 근처에서, BFS 경로탐색과 플레이어 이동 처리 모두 대각선 이동 시 벽 모서리를 스쳐 지나가는(코너 컷팅) 현상이 있다는 것을 발견했는데, 원인은 파악해뒀지만 마감 일정상 코드 수정 대신 시연 동선에서 벽 근처를 피하는 방식으로 우회하기로 결정했다.

보스 몬스터(Ancient Troll)는 기존 몬스터들과 달리 20프레임짜리 유휴 애니메이션 스프라이트로 준비되어 있었다. 프레임마다 크기가 미세하게 달라, 하나의 셀 크기로 맞춰 패딩한 뒤 가로로 이어붙인 스프라이트 시트를 만들고, 이미 프로젝트에 있었지만 아무 데도 쓰이지 않던 `CObj::Update_Frame()`(마지막 프레임에서 다시 0으로 되돌아가는 반복 재생 로직)을 재사용해서 애니메이션을 구현했다. 덕분에 새로운 애니메이션 시스템을 처음부터 짤 필요 없이, 보스 전용 `Render()`에서 스프라이트 시트의 현재 프레임 위치만큼 소스 좌표를 이동시키는 슬라이싱 로직만 추가하면 되었다.

보스전의 타격감을 위해 스크린 셰이크를 구현했다. 카메라의 실제 추적 위치(`m_fScrollX/Y`)는 그대로 두고, 별도의 셰이크 오프셋을 매 프레임 갱신해서 렌더링 시에만 더해주는 방식을 택했는데, 이 과정에서 렌더링용 스크롤 값과 마우스 클릭의 격자 좌표 변환에 쓰이는 스크롤 값을 같은 함수로 공유하고 있었다는 문제를 발견했다. 셰이크가 걸린 상태에서 클릭 공격을 하면 흔들린 오프셋만큼 좌표 계산이 어긋나 엉뚱한 칸을 공격 판정할 수 있는 상황이었어서, `Get_ScrollX()`(로직 전용, 셰이크 미반영)와 `Get_ShakeScrollX()`(렌더링 전용, 셰이크 반영)로 용도를 분리했다. 셰이크 발동 자체는 근접 몬스터 공통 로직(`CMonster_Melee::Attack/Take_Damage`)에 기본값으로 넣어두고, 보스는 자신의 오버라이드에서 더 큰 값으로 재호출해 덮어쓰는 방식으로 처리해, 모든 근접 몬스터가 타격감을 갖되 보스만 더 강하게 흔들리도록 했다.

마지막으로 게임오버 시 메뉴 화면으로 돌아가는 흐름을 연결했다. 씬 전환은 현재 실행 중인 씬 객체 스스로가 자신을 삭제하는 상황을 피하기 위해, 스테이지가 아니라 한 단계 위(`MainGame::Update()`)에서 게임오버 여부를 확인하고 전환하도록 했다. 이 과정에서 두 가지 문제를 추가로 발견해 고쳤는데, 하나는 `CStage::Release()`가 비어 있어서 씬을 나가도 몬스터/플레이어 오브젝트가 전역 오브젝트 매니저에 그대로 남아 메뉴 화면에서도 계속 그려지던 문제였고, 다른 하나는 카메라 위치가 씬과 무관하게 유지되는 탓에 재시작 시 새로 생성된 플레이어가 죽었던 위치의 카메라 값을 그대로 물려받아, 첫 이동 전까지 화면이 어긋나 보이던 문제였다. 전자는 오브젝트 매니저의 기존 정리 함수를 스테이지 종료 시 호출하도록 했고, 후자는 스테이지 초기화 시 플레이어 스폰 위치 기준으로 카메라를 즉시 맞춰주는 방식으로 해결했다.
