# 스톤샤드 턴제 RPG 모작 — 기술 구현 노트 (3)

## 1. 격자식 인벤토리 시스템

인벤토리를 씬 전환 없이 게임 플레이 화면 위에 오버레이로 띄우는 방식으로 구현했다. `Stage::Render()` 마지막에 `CInven::Render()`를 호출해 게임 화면 위에 UI가 덮여 그려지도록 했고, I키로 열고 닫는 토글 방식이다.

`CInven`은 게임 월드에 존재하는 오브젝트가 아니라 화면 고정 UI라서 `CObj` 상속 없이 독립 싱글톤 매니저로 설계했다. 인벤토리 배경은 스톤샤드 에셋(`s_inventory`, 320×360px)을 추출해 그대로 활용했고, 격자 셀 크기(27px)와 격자 시작 오프셋은 스프라이트 픽셀 분석으로 측정했다.

격자는 `CItem* m_Grid[INVEN_ROWS][INVEN_COLS]` 2차원 배열로 관리한다. 동적 크기 변경이 없고 칸 좌표로 바로 접근해야 하는 구조라 vector 대신 2차원 배열을 선택했다. 아이템 배치 시 `Place_Item()`이 아이템 크기(`m_iWidth`, `m_iHeight`)만큼 격자 칸을 해당 포인터로 채운다.

```cpp
void CInven::Place_Item(CItem* _pItem, int _iGridX, int _iGridY)
{
    for (int r = _iGridY; r < _iGridY + _pItem->Get_Height(); ++r)
        for (int c = _iGridX; c < _iGridX + _pItem->Get_Width(); ++c)
            m_Grid[r][c] = _pItem;
    _pItem->Set_GridPos(_iGridX, _iGridY);
}
```

렌더링 시 격자를 순회하면서 아이템의 좌상단 칸에서만 그리도록 체크해 중복 렌더링을 방지한다. `GdiTransparentBlt`에서 목표 크기를 `m_iWidth * 27, m_iHeight * 27`로 지정해 원본 스프라이트를 격자 칸 크기에 맞게 늘려서 그린다. `m_Grid` 배열이 아이템 크기만큼 같은 포인터로 채워지는 것은 "이 칸은 점유됐다"는 표시 용도이며, 실제 렌더링은 좌상단 한 칸에서만 한 번 처리한다.

## 2. 드래그 앤 드롭

드래그 앤 드롭 로직 흐름은 아래 자료를 참고했다.
- 출처: https://codenameus.github.io/unity/Inventory_7/
- Unity 기반이라 렌더링 방식은 달라 그대로 적용은 불가능했지만, 클릭 시작→드래그 중→클릭 해제의 흐름을 참고했다.

집기(`On_MouseDown`) → 드래그 중(`On_MouseDrag`) → 놓기(`On_MouseUp`) 세 단계로 구현했다. 마우스 픽셀 좌표를 격자 칸 번호로 변환할 때 렌더링의 역산 방식을 사용했다.

```cpp
// 렌더링: 칸 번호 → 픽셀
iPixelX = m_tInvenRect.left + m_iGridStartX + c * 27;

// 집기: 픽셀 → 칸 번호 (역산)
c = (pt.x - m_tInvenRect.left - m_iGridStartX) / 27;
```

놓기 실패 시 원위치 복귀 방식을 택했다. 드래그 시작 시점에 `m_iOriginGridX/Y`에 원래 위치를 저장해두고, `Can_Place()` 실패 시 그 위치로 되돌린다. 슬롯에서 꺼낸 아이템은 격자 위치가 없으므로 `m_iOriginGridX = -1`로 표시해 놓기 실패 시 슬롯으로 재장착하도록 구분했다.

`Key_Down(VK_LBUTTON)`이 10ms 프레임 간격으로 인해 클릭이 한 프레임 안에 처리되어 집기가 안 되는 문제가 있었다. `Key_Pressing(VK_LBUTTON) && m_pDragItem == nullptr` 조건으로 교체해 해결했다.

## 3. 아이템 클래스 설계

`CItem`은 `CObj` 상속 없이 독립 클래스로 설계했다. 인벤토리 UI 안의 아이템은 월드 좌표, 충돌 렉트 등 `CObj` 기능이 필요 없기 때문이다. 나중에 몬스터 드랍처럼 월드에 배치되는 경우는 `CObj`를 상속받는 별도 `CDropItem`으로 분리하고 `CItem`을 포함하는 구조로 확장할 예정이다.

초기에 생성자 매개변수가 10개 이상으로 늘어나 가독성이 떨어졌다. `ITEM_INFO` 구조체로 묶어 생성자를 단순화했다.

```cpp
// 수정 전
new CItem(1, 3, 15, 69, ITEM_WEAPON, 0, 0, 10, _T("..."), _T("Weapon"));

// 수정 후
ITEM_INFO tInfo = { 1, 3, 15, 69, ITEM_WEAPON, 0, 0, 10, _T("..."), _T("Weapon") };
new CItem(tInfo);
```

슬롯에 장착할 때 격자 크기(`m_iWidth * 27`)로 늘려 그리면 슬롯보다 크게 그려지는 문제가 있었다. 슬롯 전용 `Render_Original()`을 추가해 원본 크기로 그리도록 분리했다. 슬롯 중앙 정렬은 슬롯 크기에서 원본 스프라이트 크기를 빼고 2로 나눈 오프셋으로 처리했다.

## 4. 장비 슬롯 및 스탯 반영

무기/갑옷/모자 3개 슬롯을 `RECT`로 위치를 정의하고, 드래그해서 슬롯 위에 놓으면 타입을 체크해 해당 슬롯에 장착하도록 구현했다. 슬롯이 3개뿐이라 하드코딩으로 구현했으나, 슬롯이 많아지면 `EQUIP_SLOT` 구조체 배열로 관리하는 게 확장성 있다.

`Equip_Item()`에서 `CItem** pSlot` 이중 포인터로 슬롯을 선택해 실제 멤버 포인터를 직접 수정하도록 했다.

```cpp
void CInven::Equip_Item(CItem* _pItem, ITEM_TYPE _eType)
{
    CItem** pSlot = nullptr;
    switch (_eType)
    {
    case ITEM_WEAPON: pSlot = &m_pWeaponItem; break;
    case ITEM_ARMOR:  pSlot = &m_pArmorItem;  break;
    case ITEM_HAT:    pSlot = &m_pHatItem;    break;
    }
    // 기존 장착 아이템 스탯 제거 후 격자로 반환
    if (*pSlot != nullptr)
    {
        pPlayer->Add_Atk(-(*pSlot)->Get_Atk());
        pPlayer->Add_Def(-(*pSlot)->Get_Def());
        Place_Item(*pSlot, m_iOriginGridX, m_iOriginGridY);
        *pSlot = nullptr;
    }
    *pSlot = _pItem;
    // 새 아이템 스탯 적용
    pPlayer->Add_Atk(_pItem->Get_Atk());
    pPlayer->Add_Def(_pItem->Get_Def());
}
```

아이템 스탯은 `ITEM_INFO`에 `iHp`, `iDef`, `iAtk`로 분리해 정의했다. 단일 `iStat`으로 퉁치면 무기인지 방어구인지에 따라 어느 스탯에 반영할지 타입 체크가 필요해지기 때문이다.
